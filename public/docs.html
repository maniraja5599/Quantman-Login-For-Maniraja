What is FiFTO?

FiFTO (Find, Fill, Trade, Out) is a fully automated broker login system for Quantman.trade. It opens a Playwright browser, navigates to each broker's login flow, fills your credentials automatically, and closes — every morning at the scheduled time.

No manual login needed. One server runs 24/7, logs into Flattrade, Kotak NEO, and Dhan at the configured time and sends Telegram notifications about success/failure.

Login Flow (3-Step Popup)

1
Select Kotak NEO on Quantman
Open Quantman → click Login With Broker → search "kotak neo" → click card → fill Client ID.
2
Wait for Kotak Auth (New Tab / Iframe / Modal)
After clicking Login, the script polls for:
• A new tab with kotak/neo URL
• An iframe with kotak source
• An on-page modal with auth fields
3
Step A — Mobile + Client ID → Validate
Fill Registered Mobile Number + Client ID → click Validate.
4
Step B — TOTP → Validate TOTP
Auto-generates 6-digit TOTP from base32 secret → fills it → clicks Validate TOTP.
5
Step C — MPIN → Validate MPIN → Done
Fills 6-digit MPIN → clicks Validate MPIN. Checks for error messages.
💡 Kotak NEO is is_self_authenticate in Quantman — auth happens in a Kotak popup, not via redirect. The script handles new-tab, iframe, and on-page modal detection automatically.

Dhan

Script: scripts/dhan-login.js

OAuth Redirect partner-login.dhan.co

Credentials Needed

FieldDescription
DHAN_USER_IDRegistered mobile number
DHAN_TOTPBase32 secret from authenticator QR, or 6-digit code
DHAN_MPIN6-digit PIN

Login Flow (OAuth Redirect)

1
Navigate Directly to /auth/dhan
Goes to quantman.trade/auth/dhan — skips broker modal entirely. This is Dhan's registered OAuth href in Quantman.
2
Redirect to partner-login.dhan.co
Quantman immediately redirects to partner-login.dhan.co/?consentID=.... Script detects this URL.
3
Fill Mobile → Proceed
Enters your mobile number into the phone field → clicks Proceed.
4
Fill TOTP (6 Boxes) → Proceed
Generates TOTP from base32 secret → fills each of the 6 input[type="tel"] boxes one by one → clicks Proceed.
5
Fill PIN (6 Boxes) → Auto-Submit
Fills 6-digit PIN into the 6 tel boxes. Dhan auto-submits on last digit — no button click needed.
6
Redirect Back to Quantman → Done
Waits for redirect back to quantman.trade. Checks for error messages. Returns success.
⚠️ Why /auth/dhan direct navigate? Dhan's broker card in the Quantman modal uses href="/auth/dhan". The closePopups helper (needed to dismiss tips/banners) presses Escape which also closes the broker modal. Going directly to /auth/dhan bypasses this problem entirely.
💡 TOTP & PIN Input Detail: Dhan uses 6 plain input[type="tel"] boxes with zero attributes (no id, name, class, placeholder, inputmode, or maxlength). Standard OTP selectors don't match — the script detects them by type + count.
How Automation Works

The server runs a background tick every 30 seconds. At each tick, it checks if the configured time has passed today and the brokers haven't been logged in yet. If so, it triggers all selected brokers sequentially.

State is saved to config/automation.json — persists across server restarts.

Automation States

▶️ Running

Active state. Will login at the scheduled time every day. This is the normal operating state.

Auto-runs daily

⏸️ Paused

Temporarily disabled for N days. After the pause expires, automatically resumes to Running.

Auto-resumes

⏹️ Stopped

Fully disabled. No automatic logins until manually started again from the web UI or Telegram.

Manual restart needed
Schedule Configuration

Time Slots

You can configure 1 or 2 daily run times (e.g. 09:15 for market open, and 15:30 for afternoon).

# Example: single time runAt: "09:15" runAt2: null # Example: two times per day runAt: "09:15" runAt2: "15:30"

Broker Selection

Each broker can be individually enabled/disabled for automation:

brokers: { flattrade: true, // ✅ included kotakNeo: true, // ✅ included dhan: false // ❌ skipped }
💡 120s Startup Grace: On server start, automation waits 2 minutes before running its first tick. This prevents false triggers immediately after a server restart.
⚠️ Schedule Change Guard: If you change the run time to a past time today, the system skips that day to prevent an immediate run. It'll run normally starting tomorrow.
Run Lock

Only one login run can happen at a time. If a run is already in progress (manual or automated), any new trigger returns a busy error. This prevents parallel browser sessions.

Key Files Explained

🖥️ server.js

The heart of the project. Contains:

  • Express REST API (all /api routes)
  • Automation tick loop (30s interval)
  • Subprocess runner for login scripts
  • Telegram sender + control polling
  • Credentials loader (JSON + .env merge)
  • Activity log management

📄 config/credentials.json

Stores credentials saved via the Settings UI. Values here override .env values.

{ "kotakNeo": { "clientId": "YXLLE", ... }, "dhan": { "userId": "9159...", ... }, "telegram": { "enabled": true, ... } }

📄 config/automation.json

Persisted automation state. Survives server restarts.

{ "enabled": true, "state": "running", "runAt": "09:15", "runAt2": null, "brokers": { "dhan": true, ... }, "lastAttemptDate": "2026-06-06" }

🎭 scripts/*.js

Each script is standalone — can be run directly or via the server subprocess runner. They export a runXxxLogin(options) function and also have a main() for CLI use.

Data Flow
1
Trigger (Manual or Scheduled)
Via web UI button, API call, Telegram /run, or automation tick.
2
Run Lock Check
If already running → return busy. If free → acquire lock.
3
Spawn Subprocess
server.js spawns node scripts/xxx-login.js as a child process with credentials injected as env vars. 2-minute timeout.
4
Script Runs Playwright
Browser opens, fills credentials, returns JSON {"success":true,"step":"done"} via stdout.
5
Parse Result → Update Status
Server parses stdout JSON, updates statusStore, logs activity, sends Telegram notification.
6
Release Lock → Return Response
Run lock released. Result returned to caller (UI, Telegram, or automation engine).
